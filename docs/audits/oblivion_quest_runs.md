# Oblivion quest-run worklog (2026-11-11 ..), organized by quest

Companion to [mwscript_full_runs.md](mwscript_full_runs.md). **Every standing rule there applies here
unchanged** (user, 11-12: "follow all the same morrowind test rules"): fix-and-resume, 3 passes per changed
case, no route-forcing legs, place the player when no follower is along, `approach`-style placement instead of
waiting for an NPC, SetDisposition for persuasion, generic fixes only, no docs/tests before in-game confirmation.

## 🛑 Lessons specific to TES4 runs (read before touching a case)
- **The user has played by hand from chargen up to delivering Martin to Cloud Ruler Temple (end of MQ04), and
  no further** (user, 11-12). Up to there a failure is the CASE or the HARNESS first (user, 11-12, twice): don't
  reach for the converter until the case does what a player does. **From MQ05 on nothing is hand-verified and
  "it likely has more bugs than we have seen so far"**: treat a failure as a likely conversion bug, find its
  cause from the snapshot and the export, fix it generically, and never reshape the case to get past it.
- **Don't redo Morrowind's work.** Its runner solved timing, placement, dialogue and walking; look there first.
  🛑 User, 11-13 ("again"): a step Morrowind's cases have (`follow`, `defend`, ...) must work in every game's
  cases through the SAME code -- it is base Skyrim functionality. Never write a second implementation or a
  case-side stand-in (repeated `player.moveto`, a new hook): expose MorrowindRuntime's own call (an export taking
  runtime FormIDs, as `defend` / `pace` / `follow` do) and bind it in tes/test_game.cpp.
- **Never place the player INSIDE a trigger box.** A moveto/setpos into one throws the player elsewhere in the
  cell (chargen cell trigger: landed on CGMarkerAmbushAGlenroy / Renote's marker, 2,600 away). Walk in, as the
  Morroblivion dock case does.
- **A walk "to" a trigger can stop short.** `walk` arrives within 128 on the ground plane; Oblivion's
  TrigZone02 box is 410 x 41 x 292 (bhkBoxShape 2.94/0.29/2.09 x 70), so walk to a floor point PAST it.
- **A topic's result script runs after the answer's last line**: check what it sets with `until`, not `expect`.
- **Skyrim lists a line's new topics only once the line is spoken**: `ask` now waits for its topic.
- **Ask after a greeting's LAST line**: a click between two lines of a multi-line greeting is lost (2r).
- **No case boundary near a greeting**: the harness's checkpoint save (even a failed one, while chargen holds the
  controls) closes an open or opening conversation (1w, 1x, 2b, 2d). Keep a force-greet, its topics and any menu
  re-greet in ONE case, with the boundary at a quiet moment (before a fight, after the last topic).
- **A force-greeter is walked up to, not teleported to**: a teleport into a Skyrim ForceGreet's range gave no
  greeting or lost the menu (1q, 1r, 1t, 1u); a short `walk <npc>` (his greeting ends it) works (1v).
- **Class/answer lines have variants**: `hear` the words they share -- and that NO EARLIER untaken line says
  ("rats and goblins" also matched the answer before the menu, 2i; use "any trouble").
- **Skyrim keeps the Dialogue Menu open under a TES4_Chargen.Ask menu** (2i).
- **Doors: check XLOC before routing through one.** Level 100 + no key = only a script opens it.
- **A case boundary must be a moment where the quest WAITS FOR THE PLAYER.** The game keeps running between a
  resumed save's load and the case's first step (at test pace a whole fight and force-greet fit there, 2g).
- **Saves fail while chargen has controls disabled** (`checkpoint ... NOT SAVED`): resume from the last case
  that saved, not the failed one.

## Launch
- Build: `test_instance --instance N build --mod Oblivion.esm --mod TESGameSelect` (without TESGameSelect there
  is no game picker: "no game selector prompt after New Game").
- New game: `questtest --cases tes_runtime/tes/testdata/quests/oblivion_main --new-game 1 --fast --checkpoints
  --stop-on-fail --timeout 3600` (button 1 = Cyrodiil). Resume: `--from <case>`; one case: `--from X --to X`.
- `--fast` already runs `tgm`; a case must not toggle it again.
- Live probes: temp/tes4_probe.py (`!cmd` raw, `@HEXREF cmd` at a ref, else TES4 names resolved).
- Fixed 11-12: the harness swapped console keywords that are also Oblivion EditorIDs (`z` -> 0517D41C, `player`
  -> 05000007): tes4_cases.CONSOLE_WORDS keeps player/x/y/z. A `run` line the engine rejects with a message
  (not "unknown command") does NOT fail the case -- check placements with an `expect`.
- A cross-cell `moveto` lands a few frames later: a `setpos` in the same `run` block is overridden. Put `wait`
  between them.
